# Pipe 连接大 QMT：简明流程

适用：本项目 `integrations/bigqmt_pipe`，外部 Python 与大 QMT 在**同一台 Windows 电脑**。这里的 Pipe 是 Windows 命名管道，无需启动 Redis。

流程：**登录大 QMT → 运行桥接模型 → 核对客户端配置 → 本地检查 → 只读连通检查**。

## 统一账号（2026-11-13 更新）

日常只修改项目根目录 [trading_account.txt](../../trading_account.txt)，用 `#` 注释暂不使用的账号，始终只保留一个未注释账号。支持空行和行尾备注；全部注释或同时启用多个账号会报错。

```text
8890697593  # 当前账户
# 8890145315  # 备用账户；切换时注释上一行，再取消本行注释
```

Pipe 客户端和 `Stragety/MiniQMT_Stragety/core/config.py` 直接读取此文件；更换账号后重新启动相关外部 Python 进程。该共享配置影响所有使用它的策略，其他自带账号配置的策略不在此次接入范围内。

QMT 单文件模型独立部署，更新账号后执行：

```powershell
# 把统一账号写入仓库部署快照，再将完整源码更新到 QMT 模型
python integrations\bigqmt_pipe\sync_account.py

# 也可以直接更新指定的 QMT 源码文件；不会启动或停止模型
python integrations\bigqmt_pipe\sync_account.py --qmt-source "C:\QMT_8890697593\python\PIPE_ASCII_ALL_IN_ONE.py"
```

同步只修改账号，保留原编码、其他配置和下单权限。随后在 QMT 中重新编译、加载模型才会生效；已有持仓、账本和运行中的进程不会自动切换账号。

## 1. 在大 QMT 中运行桥接模型

1. 启动并登录大 QMT，确认目标资金账户可用。
2. 若 `PIPE_ASCII_ALL_IN_ONE` 模型已正常运行，直接进入第 2 步，无需重建。
3. 首次部署：新建 Python 模型，复制 [PIPE_ASCII_ALL_IN_ONE.py](deploy/PIPE_ASCII_ALL_IN_ONE.py) 的完整源码。
4. 在源码顶部核对以下配置，编译保存，然后放入**模型交易**运行，**不勾选独立 Python 进程**。

```python
BIGQMT_ACCOUNT_ID = "你的资金账号"
BIGQMT_ACCOUNT_TYPE = "STOCK"
```

源码顶部 `BIGQMT_REDIS_CONFIG` 中保持：

```python
"transport": "pipe",
"redis_enabled": False,
"pipe": {"pipe_name": "bigqmt_rpc"},
"rpc_allow_order_methods": False,
"native_xtdata_enabled": False,
```

以上只表示需核对的配置项，不要用这几行替换整个配置字典。单文件模型直接读取顶部配置，修改外部 `local_config.py` 不会影响它。运行后保持 QMT 和桥接模型开启。

## 2. 配置外部 Python 客户端

打开 `src/bigqmt_signal_trader_client_config.py`；文件不存在时，复制同目录的 `bigqmt_signal_trader_client_config.example.py` 并去掉文件名中的 `.example`。

- `BIGQMT_ACCOUNT_ID`：保留模板中的读取逻辑，账号统一在根目录 `trading_account.txt` 修改。
- `BIGQMT_REDIS_CONFIG`：`transport="pipe"`、`redis_enabled=False`。
- `pipe_name="bigqmt_rpc"`：与 QMT 端一致。
- `BIGQMT_FORMULA_SERVER_CONFIG`：`enabled=False`。

变量名中的 `REDIS` 是兼容命名，实际使用 Pipe。

## 3. 安装依赖并检查连接

在 PowerShell 中执行；`python` 应指向准备运行策略的 Python 环境：

```powershell
cd C:\03MyProj\QMT-expert
python -m pip install -r integrations\bigqmt_pipe\requirements.txt

# 仅检查本地配置，不连接 QMT、不运行策略
python run_bigqmt.py --bridge pipe --check

# 连接 QMT，只读查询服务、资金、持仓，不运行策略
python run_bigqmt.py --bridge pipe --probe
```

**连接成功标准：**输出 `transport=pipe`；`ping` 返回 `pong` 且账号正确；资金和持仓查询无异常。空持仓本身不代表连接失败。

两个命令默认检查启动器指定的默认策略，并核对其账号。要检查其他策略，在命令后追加 `--strategy "策略文件完整路径"`。

## 4. 连接成功后运行策略（可选）

```powershell
# 默认 v41 策略：信号模式，不发委托
python run_bigqmt.py --bridge pipe --mode signal
```

其他策略通过 `--strategy` 指定，模式参数以该策略说明为准。部署快照默认关闭下单和撤单；2026-11-13 本机实际服务的 `--probe` 返回 `allow_order_methods=True`，应以运行中服务返回为准。本次未修改权限，查询成功仅代表读取连通，不代表实盘交易已验证。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| `--check` 成功但连不上 | `--check` 不检查连接，继续执行 `--probe` |
| 管道连接失败或超时 | 确认同机运行、QMT 已登录、桥接模型正在模型交易中运行，两端账号与管道名一致；检查 Windows 权限限制 |
| 提示账号不一致 | 核对统一账号文件；旧客户端配置升级为示例中的读取逻辑；其他自带配置的策略仍须显式核对 |
| 输出 `transport=redis` | 明确使用 `--bridge pipe`，并核对 Pipe 客户端配置 |
