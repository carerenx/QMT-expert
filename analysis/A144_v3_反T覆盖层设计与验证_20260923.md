# A144 v3 反T覆盖层设计与验证

## 结论

已实现 A144 v3 反T覆盖层。v3 完整保留 v2 的日线选股、风险预算、弱势退出和槽位冻结；新增机制只管理 A144 自有底仓的日内先卖后买，不接管账户中的外部持仓。

状态机、订单归属、持仓范围、60%整手计算、强制回补和版本迁移已通过自动测试。2026-09-24 的分钟回测表明：严格1分钟数据覆盖不足；5分钟扩大样本敏感性检验中，当前参数显著拖累收益，因而当前版本不通过实盘部署闸门。详见 `analysis/A144_v3_反T回测报告_20260924.md`。

## 交易机制

- 只做反T，不做正T。
- 支持多只 A144 持仓同时独立运行。
- 每只股票每日最多一个反T周期。
- 每次卖出 `min(账户可卖数量, A144归属数量)` 的60%，向下取整为100股整手；只要至少有1手，最低卖100股。
- 当天新买入的 A144 持仓不参与反T。
- 卖出信号采用“达到 ATR 自适应阈值后继续上冲，再回落确认”，避免首次碰线立即卖出。
- 实际卖出成交后，按实际成交价计算回补触发线；触线后等待价格从低点反弹0.10%再买回。
- 卖出后继续上涨2%时紧急买回；14:50仍未回补时强制尝试买回。
- 跨日仍有未回补腿时，下次运行优先恢复买回。

## 与 A144 底仓的边界

- A144 checkpoint 中的 `owned.shares` 始终表示目标底仓，不因完整反T周期改变。
- 反T使用独立 `dayt_checkpoint_redisqmt_a144_v3.json`，记录卖出数量、实际成交价、订单ID、回补价格和价差。
- 反T订单标签使用 `A144V3T-日期-代码-S/B-序号`。
- 存在未回补反T腿时，v3 的日线 `plan` 和 `execute` 均被阻断。
- 已存在 A144 清仓计划的股票，清仓计划拥有卖出优先权，反T禁止开新腿。
- 账户持仓少于 A144 归属数量时，禁止新开反T并输出错误。
- 账户其他策略持仓不会扩大反T可卖数量。

## 运行

首次从 v2 切换且 v2 已有归属持仓时，先执行显式迁移：

```text
python Stragety/RedisQMT/A144/A144_v3_ReverseTOverlay.py migrate-v2 --mode live --confirm MIGRATE
```

观察模式不下真实订单、不写入实盘反T状态：

```text
python Stragety/RedisQMT/A144/A144_v3_ReverseTOverlay.py dayt --mode signal
```

单次只读观察：

```text
python Stragety/RedisQMT/A144/A144_v3_ReverseTOverlay.py dayt --mode signal --once
```

实盘反T循环：

```text
python Stragety/RedisQMT/A144/A144_v3_ReverseTOverlay.py dayt --mode live --confirm LIVE
```

日线计划与执行仍使用原流程，但必须改为 v3 文件：

```text
python Stragety/RedisQMT/A144/A144_v3_ReverseTOverlay.py plan
python Stragety/RedisQMT/A144/A144_v3_ReverseTOverlay.py execute --mode live --confirm LIVE
```

查看反T状态：

```text
python Stragety/RedisQMT/A144/A144_v3_ReverseTOverlay.py dayt-status
```
