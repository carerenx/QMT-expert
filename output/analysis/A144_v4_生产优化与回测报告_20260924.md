# A144 v4 生产优化与回测报告

## 最终结论

已把 `A144_v4_CandidateReplacement.py` 调整为可部署的 **日线实盘版**：

- A144 日线主体允许 `plan / execute / check` 实盘运行。
- 反 T 与候补替代保留为 `signal` 影子观察。
- `dayt --mode live` 被生产闸门强制拒绝，不能因误输参数而下单。

这是当前证据下唯一可以合理称为“可实盘”的 v4 配置。它不是把尚未通过验证的候补机制包装成实盘，而是让已经回测的日线主体进入生产路径，同时隔离负贡献的 DayT 层。

## 优化过程

### 1. 反 T 参数筛选

对 5 个参数进行 162 组组合回放：

- 卖出 ATR 倍数：0.40 / 0.60 / 0.80
- 最低上涨阈值：1.2% / 1.6% / 2.0%
- 突破后延伸：0.15% / 0.30% / 0.50%
- 高点回落确认：0.20% / 0.40% / 0.60%
- 确认采样数：2 / 3

参数只用 2026-08-14 以前的数据选择，之后的数据冻结为验证集。旧强制/紧急回补仍作为未闭合腿的保守损失计入，避免删除亏损分支后虚增成绩。

训练期最优组合把损失从 -8,142.05 元缩小到 -931.98 元，但验证期仍亏损 10,121.16 元，而且坏腿比例从基准的 40.00% 上升到 46.67%，未通过验证闸门。参数不写入生产配置。

### 2. 候补排序筛选

保持原始 Alpha144 Top 15% 和全部入场条件不变，只比较 7 种候补排序：原始 Alpha、质量、长短动量及其固定权重组合。

- 训练期：2022-01-04 至 2024-12-31，307 个每日候补样本。
- 样本外：2025-01-02 以后，205 个每日候补样本。
- 观察期限：5 / 10 / 20 个交易日，含买卖费用。

训练期选出的 `alpha_quality40` 在样本外的 20 日平均收益从原始排序的 3.579%下降到2.421%，中位数也从 +0.172%下降到 -0.043%，没有通过均值、中位数和尾部风险同时改善的预设闸门。生产版继续保留原始 Alpha144 排序，不采用过拟合权重。

更重要的是，原始排序全样本 512 次的 20 日收益中位数为 -1.205%，胜率仅 43.55%。候补的正均值来自右尾赢家，而不是稳定的多数胜率，因此不能让候补替代自动实盘。

### 3. 个股顶部风险验证

信号验证工具对最大输家 603719.SH 和最大赢家 688185.SH 分别检查了 500 个交易日、18 类顶部/动量信号。

两只股票在替代附近都出现过布林上轨突破，但后续方向显著不同：603719.SH 的 2026-08-03 信号后20日收益为 -2.4%，688185.SH 的 2026-08-11 信号后20日收益为 +28.6%。用单一“过热/逃顶”规则过滤候补，会同时删除输家和大赢家，不能稳定提高收益。因此本轮没有增加事后顶部过滤器。

## 实盘安全改动

`config_v4.py` 新增：

```python
DAYT_LIVE_ENABLED = False
```

`live_runtime_v4.py` 在创建 RedisQMT 实盘适配器前执行生产闸门：

- `dayt --mode live`：拒绝。
- `dayt --mode signal`：允许，只观察、不落盘、不下单。
- `plan / execute / check`：允许走原有日线生产流程。

原有实盘保护继续保留：显式 `LIVE` 确认、独立策略订单标签、checkpoint 归属、迁移持仓核对、同信号日计划幂等、未闭合腿阻断日线执行。

## 实盘运行

### 1. 首次切换

若当前归属在 v3：

```powershell
python Stragety\RedisQMT\A144\A144_v4_CandidateReplacement.py migrate-v3 --mode live --confirm MIGRATE
```

若当前归属在 v2：

```powershell
python Stragety\RedisQMT\A144\A144_v4_CandidateReplacement.py migrate-v2 --mode live --confirm MIGRATE
```

迁移前必须确认不存在未回补的反 T 腿。迁移命令会读取真实账户持仓并核对 checkpoint，不会发送买卖委托。

### 2. 只读检查

```powershell
python Stragety\RedisQMT\A144\A144_v4_CandidateReplacement.py check --mode live
```

### 3. 收盘后生成计划

```powershell
python Stragety\RedisQMT\A144\A144_v4_CandidateReplacement.py plan --mode signal
```

应在完整日线形成后运行。若计划使用了当日数据，程序要求时间晚于15:05。

### 4. 下一交易日执行

人工检查计划文件后：

```powershell
python Stragety\RedisQMT\A144\A144_v4_CandidateReplacement.py execute --mode live --confirm LIVE
```

### 5. DayT影子观察

```powershell
python Stragety\RedisQMT\A144\A144_v4_CandidateReplacement.py dayt --mode signal
```

即使输入以下命令，也会被生产闸门拒绝：

```powershell
python Stragety\RedisQMT\A144\A144_v4_CandidateReplacement.py dayt --mode live --confirm LIVE
```

## 验证结果

- v3/v4 定向回归：19项通过。
- v4 生产回测脚本正常完成。
- DayT live 拒绝路径已通过单元测试和命令行冒烟测试。
- RedisQMT 实盘只读 `check` 已成功连接账户并返回现金及2个持仓；没有生成计划或发送委托。
- Python 编译检查通过。
- QMT 官方预提取文档目录在当前工作区不存在；本轮没有新增 QMT API，只为现有 RedisQMT 调用增加本地生产闸门。

## 限制

日线回测仍使用当前中证500成分股快照，存在生存者偏差；DayT 5分钟数据只覆盖15.3%的可交易持仓日，严格1分钟证据仍不足。因此，“可实盘”特指代码执行与风险边界已经收紧，**不等于未来收益保证，也不等于 DayT 已获准实盘**。
