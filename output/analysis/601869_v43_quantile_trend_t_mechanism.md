# 601869 v43 分位趋势做T机制说明

## 1. 目的与边界

策略文件：`Stragety/MiniQMT_Stragety/DayT/DayT_v43_QuantileTrendT.py`  
核心计算：`Stragety/MiniQMT_Stragety/core/quantile_trend_regime.py`

v43 的目标不是预测明天涨跌，也不是在判定“牛市”后完全停止反T。它只回答一个更直接的问题：

> 在当前趋势强度下，历史上次日从开盘到盘中最高价的上涨幅度通常处于什么位置？

这个位置被用来决定反T的启动价。趋势越强，启动价越靠近历史上涨幅度的高分位，以减少过早卖出；趋势越弱，启动价越靠近低分位，以提高可触达性。

本机制只替换反T的**启动阈值**。触价以后仍必须等冲高回落确认才会卖出；卖出后仍按原有买回逻辑执行。因此它不是“价格碰到阈值立即卖出”的机制。

## 2. 与 v42 线性机制的差异

| 项目 | v42 自适应线性 | v43 分位趋势 |
|---|---|---|
| 核心模型 | 多因子线性回归 | 当前趋势在自身历史中的排序 |
| 因子 | 趋势、动量、回撤、波动、成交量 | ATR 标准化趋势；成交量仅用于满足输入长度，当前不参与公式 |
| 阈值来源 | 回归均值与低尾部的混合 | 历史“次日开盘到最高价”幅度的分位数 |
| 牛市处理 | 线性判为 bull 时曾直接禁止反T | 仅最强历史趋势尾部禁止；普通强势趋势提高卖点，仍可反T |
| 可解释性 | 需追踪各因子系数和混合比例 | `趋势排名 → 目标分位 → ATR 单位`，链路较短 |

v42 的主要问题是：当线性分数刚越过 bull 边界，就可能直接把 `do_short` 设为 `False`；而尚未达到极端趋势的上涨日，也可能因低尾部混合而把阈值压得太低。v43 将“是否极端强势”和“卖点需要多高”拆开处理。

## 3. 数据窗口和参数

当前参数位于 `quantile_trend_regime.py` 文件开头：

```python
HISTORY_DAYS = 80
LOOKBACK_EXPONENT = 0.5
MIN_HISTORY = 30
MIN_SPAN = 3
MIN_ATR_PERIOD = 2
```

含义如下：

- `HISTORY_DAYS=80`：最多使用最近 80 个已完成日线。它是样本容量上限，不是固定预测周期。
- `LOOKBACK_EXPONENT=0.5`：趋势和 ATR 的窗口为 `int(样本数 ** 0.5)`。当有 80 个样本时，窗口为 8 日。
- `MIN_HISTORY=30`：少于 30 日线时不启用 v43，保留原信号，避免小样本分位数失真。
- `MIN_SPAN=3` 与 `MIN_ATR_PERIOD=2`：保证趋势和 ATR 至少有足够计算长度。

在 80 日样本、8 日窗口下，可用于“次日上涨幅度”统计的样本约为：

```text
80 - 8 - 1 = 71 个
```

实际数量会因 ATR 无效、价格为零等异常行略少。

## 4. 计算过程

### 4.1 当期趋势分数

令：

- `C_t`：最新已完成日收盘价；
- `MA_span(t)`：最近 `span` 日收盘均值；
- `ATR_t`：同一窗口计算的 ATR。

趋势分数为：

```text
trend_score = (C_t - MA_span(t)) / ATR_t
```

它不是百分比，而是“收盘相对短期均线偏离了多少个 ATR”。例如 `+1.20` 表示收盘大致在短期均线之上 1.2 个 ATR；`-0.80` 则在均线下方 0.8 个 ATR。

### 4.2 趋势排名

脚本会对每个历史日按同一公式计算 `trend_score`，再计算当前分数在历史中的经验分位：

```text
trend_rank = 历史 trend_score <= 当前 trend_score 的个数 / 历史样本数
```

`trend_rank` 的范围是 0 到 1：

- 接近 `0`：当前趋势是近期最弱的一档；
- 接近 `0.5`：中性；
- 接近 `1`：当前趋势是近期最强的一档。

### 4.3 历史可实现上涨幅度

对历史第 `i` 日，策略不拿当日高点作为标签，而取**下一交易日** `i+1` 的开盘到最高价：

```text
excursion_i = (high_(i+1) / open_(i+1) - 1) / ATR%_i
ATR%_i = ATR_i / close_i
```

因此 `excursion_i` 的单位是 ATR。例如 `0.40` 表示次日开盘后曾上涨约 `0.40 × ATR%`。使用下一日数据可避免“用当天最高价决定当天开盘卖点”的未来数据泄漏。

### 4.4 从趋势排名映射到目标分位

尾部边界由样本数自动决定：

```text
tail_rank = 1 / int(sample_count ** LOOKBACK_EXPONENT)
```

假设有约 71 个样本、指数为 `0.5`，则 `tail_rank` 约为 `0.125`。目标分位为：

```text
trigger_quantile = tail_rank + trend_rank × (1 - 2 × tail_rank)
```

该映射的效果：

| `trend_rank` | `trigger_quantile`（tail=0.125 时） | 含义 |
|---:|---:|---|
| 0.00 | 0.125 | 弱势：取较低分位，增加触发机会 |
| 0.50 | 0.500 | 中性：取历史中位水平 |
| 1.00 | 0.875 | 强势：只接受更高的冲高空间 |

这是连续变化的，不存在 v42 那种“刚跨越 bull 边界、阈值和交易许可突然跳变”的普通分段。

### 4.5 卖出启动价

从全部历史 `excursion` 中取上述分位数：

```text
quantile_units = Quantile(excursion, trigger_quantile)
trigger_pct    = 当前 ATR% × quantile_units
sell_trigger   = 当日信号基准价 × (1 + trigger_pct)
```

信号基准价优先使用当天开盘 tick；收盘后运行时使用当日已完成收盘价。日志会输出：

```text
[QUANTILE-TREND] score +... | rank ... | trigger-Q ... | samples ... | span ...d | ATR-units ...
[QUANTILE-FORMULA] units=Quantile(next-day open-to-high,
 tail ... + trend-rank ...*(1-2*tail)) = Q... -> ...
```

例如 `ATR=7.52%`、`quantile_units=0.50`、信号基准价 `390` 时：

```text
sell_trigger = 390 × (1 + 7.52% × 0.50) = 404.66
```

## 5. 反T的实际执行路径

分位趋势阈值只是第一层。完整反T链路如下：

```text
健康日线通过
  → v43 计算 sell_trigger
  → 有可卖底仓且未被风险条件阻断
  → 最新价 >= sell_trigger：进入 SPIKING，记录峰值
  → 峰值回落 >= PULLBACK_PCT（当前 0.10%）：提交卖单
  → 卖出后按成交价计算买回目标
  → 下跌触及买回区后，按原有探底/反弹逻辑买回
```

因此，价格仅短暂穿越 `sell_trigger` 而没有回落时，不会立即卖掉，也不会错过继续上冲的收益。这是对“阈值 393 被触发、后来涨到 404”的直接改进：v43 同时提高强势趋势下的启动价，并保留冲高回落确认。

## 6. 牛熊状态和阻断规则

v43 的 `style` 不再代表宏观市场牛熊，只是当前个股趋势在最近样本中的相对位置：

- `bear`：`trend_rank <= tail_rank`，近期最弱一小段；阈值偏低，但仍经过成交量、RSI、涨停保护、仓位与状态机检查。
- `sideways`：中间绝大多数情况；阈值随排名连续移动，允许反T。
- `bull`：`trend_rank >= 1 - tail_rank`，即近期最强的一小段；`do_short=False`，日志显示 `extreme trend-rank guard`。

以 71 个样本、`tail_rank≈0.125` 举例，只有排名约前 12.5% 的极端趋势会禁止新增反T。普通上涨不是被禁止，而是把启动价抬高。

仍然可能阻断反T的独立条件包括：可卖底仓不足一手、日内交易次数已满、成交量/RSI等原有信号过滤、临近涨停保护、日线健康检查失败、或订单状态机处于不允许开新腿的状态。这些不是分位趋势模型的判定结果。

## 7. 收盘后日线确认机制

共享连接模块 `DayT/infra/connector.py` 现在增加了收盘确认规则：

- `15:10:00` 前：当天日线视为形成中，主动剔除；最新完整日线应为上一交易日。
- `15:10:00` 后：保留当天日线，并把健康检查期望日期设为当天。
- 收盘后若行情源仍没有当天日线：记录 `DATA-STALE`，初始化安全锁定，不使用昨天数据生成“当天已完成”的信号。

对应日志：

```text
[DailyData] retained post-close current-day bar 20260908 (after 15:10:00)
[DATA-HEALTH] last_complete=20260908 expected=20260908 ... status=OK
```

这一步不改变日内开盘时的信号逻辑；它防止收盘后复盘或重启时，将上一日收盘误当作当前最新完整日线。

## 8. 已完成的验证与尚不能证明的事项

### 已验证

1. `connector.py` 已通过 Python 编译检查。
2. 模拟两根日线验证：盘中会剔除当天；15:10 后会保留当天。
3. 模拟收盘后日线齐全时，健康检查得到 `last_complete=expected=20260908`。
4. 模拟收盘后行情源只返回 `20260907` 时，健康检查返回失败并记录 `DATA-STALE`。

### 尚不能由日线直接证明

日线只有开高低收，不能判断“先冲高，再回落到卖出确认位，再下跌到买回位”的分钟级先后顺序。因此任何只基于日线的触发率或收益统计，都只能作为候选阈值的筛选代理，不能视为实盘收益承诺。

上线前应至少使用分钟级或逐笔数据复盘以下三件事：触价后回落确认的实际比例、卖出后当日可买回比例、以及没有及时买回时的尾部风险。v43 当前应先以 `--mode signal` 观察一段样本，再决定是否用于实盘。
