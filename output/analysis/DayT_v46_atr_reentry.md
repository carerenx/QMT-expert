# v46：平仓成交价锚定的ATR下一轮阈值

策略文件：`Stragety/MiniQMT_Stragety/DayT/DayT_v46_ATRReentry.py`。
本版本独立包含v45多持仓策略代码；账户中每只股票分别计算下一轮阈值。

## 触发时机

第一轮保留原有分位趋势启动逻辑。反T全部买回，或正T全部卖回后，才计算下一轮阈值；部分平仓不触发。如果有阶梯多腿，等待当前该方向全部平仓，不在只平掉其中一手时重设。

基准P取完成平仓的最后一笔订单的实际成交均价。它不是最新行情、委托价或当天VWAP；多笔订单分批平仓时，使用最终完成平仓那笔订单的均价，不是所有平仓订单的加权均价。

订单信息按本次提交返回的订单ID查询，并校验股票、订单ID、成交数量和均价。若查询暂时未返回有效信息，输出`NEXT-T WAIT`，每5秒尝试重算一次，等待期间禁止新增交易腿；原有未平仓腿的退出目标不变。无有效ATR历史时同样等待，不回退到旧阈值继续开仓。

## ATR与历史系数

使用该股票最近最多80根已完成日线，ATR周期为`int(n ** 0.5)`。使用前一日可知的ATR标准化下一日波动：

```text
历史上行单位[i] = max(0, high[i+1]/open[i+1]-1) / (ATR[i]/close[i])
历史下行单位[i] = max(0, 1-low[i+1]/open[i+1]) / (ATR[i]/close[i])
k_up   = 历史上行单位的50%分位
k_down = 历史下行单位的50%分位
ATR%   = 最新已完成日的ATR / 最新已完成日收盘价

下一轮反T启动价 = P × (1 + ATR% × k_up)
下一轮正T启动价 = P × (1 - ATR% × k_down)
```

上下行分别计算，因此不会假定上涨与下跌空间对称。系数由样本决定；ATR来自已完成日线，同一交易日通常不变。每轮更新的是平仓基准价，不是用未完成日线实时重算ATR。

卖点向上取整、买点向下取整到0.01元，距离基准至少一个价位。计算完成后两条主做T启动线冻结，直到下一次完整平仓或下一交易日重新初始化。达到阈值仍需原有冲高回落/探底反弹确认。

## 参数位置

`Stragety/MiniQMT_Stragety/core/atr_reentry.py`开头：

| 参数 | 默认 | 含义 |
|---|---:|---|
| REENTRY_HISTORY_DAYS | 80 | 完成日线样本上限 |
| REENTRY_LOOKBACK_EXPONENT | 0.5 | ATR窗口指数 |
| REENTRY_QUANTILE | 0.5 | 历史上下行幅度采用的分位；增大拉宽距离，减小缩短距离 |
| REENTRY_MIN_HISTORY | 30 | 最少历史长度 |
| REENTRY_PRICE_TICK | 0.01 | 启动价取整单位 |

这不是持仓成本保护，不使用股票持仓成本价限制交易。MOM完成后也会更新主做T阈值；MOM自身仍采用原来的分钟动量触发条件，本次未替换该独立触发器。

## 示例（构造数据，不是600584实时测算）

若最终平仓均价69元，ATR为6%，历史中位上行单位为0.6667、下行单位为0.3333：

```text
REV ≈ 69 × (1 + 6% × 0.6667) = 71.76元
FWD ≈ 69 × (1 - 6% × 0.3333) = 67.62元
```

不能仅凭`Y69.68 / REV70.66 / FWD67.69`日志算出真实新阈值，还需要该股票的历史波动与实际平仓成交均价。代码会在平仓时输出完整`NEXT-T`公式日志。

历史开盘到高低点的幅度只是再次入场间距的参考，不代表平仓后剩余时间一定能达到该间距。本次验证为离线功能测试，不是收益或触发率回测。

## 运行

```powershell
python run_bigqmt.py --strategy Stragety\MiniQMT_Stragety\DayT\DayT_v46_ATRReentry.py --mode signal
```

实盘参数为`--mode live`。信号模式不会下单，因此不会产生真实成交后的重入日志；该路径通过离线模拟成交测试验证。不要与旧版实盘策略并行操作相同持仓；新进程不恢复旧进程未完成交易腿。

实际订单查询与成交均价字段已对照仓库BigQMT兼容层`integrations/bigqmt/src/bigqmt_signal_trader/xtquant_compat.py`中的`query_stock_order`及`_order_from_dict`实现核对。此次没有连接实际账户下单验证。
