# A144 v4 候补替代机制设计与验证

## 结论

已新建 `A144_v4_CandidateReplacement.py`，没有覆盖 v3 历史版本。

v4 删除了两个造成主要回测亏损的原票回补分支：

- 删除“卖出后继续上涨2%时紧急买回原票”。
- 删除“14:50强制买回原票”。

正常回落回补保留。若14:50仍未形成正常回补，策略使用该次卖出释放的资金，买入前一完整交易日 A144 候补池中排名最高、当前未持有且可以买到至少一手的股票。

当前状态为“已实现、回测证据不足”。自动测试证明状态迁移、资金取整、归属转移和防重复拆仓符合设计。后续已补充动态候补的5分钟配对回测：5个独立底仓周期中4个可完整估值，表面净贡献为正，但几乎全部来自单只极端赢家；剔除该赢家后相对不做T净亏2,335.55元，因此仍不能进入实盘。详见 `analysis/A144_v4_候补替代回测报告_20260924.md`。

## 状态路径

```text
WATCH → ARMED → SOLD
                    ├─ 达到回补目标并反弹 → 正常买回原票 → DONE
                    └─ 14:50仍未正常回补 → 买入A144候补 → REPLACED
```

不存在以下路径：

```text
上涨2% → 紧急买回原票
14:50 → 强制买回原票
```

若候补池为空、现金不足一手或订单未成交，原卖出腿保持未闭合状态，日线 `plan/execute` 继续被阻断；策略在后续轮询和下一交易日继续寻找候补，不会偷偷恢复成强制买回原票。

## 候补池定义

候补使用前一完整交易日数据，避免使用尚未结束的当日K线：

1. 市场过滤通过。
2. 位于 Alpha144 排名前15%。
3. 通过现有突破、放量、趋势、动量、流动性和路径过滤。
4. 不在 A144 当前归属持仓中。
5. 账户中不存在外部持仓。
6. 不在冷却期，也没有被其他替代腿占用。

候补按 Alpha144 因子从高到低选择。14:40起只要存在未回补腿，运行时会提前加载候补池，避免14:50才查询全市场而错过收盘。买入预算为原票卖出成交金额，最多使用可用现金与预算较小者的98%，股数向下取整到100股。

## 归属和防拆分

候补成交后同步完成两个 checkpoint 变更：

- 从原票 A144 归属股数中扣除已卖数量。
- 将候补实际成交数量加入 A144 归属，记录候补成交价、日期和替代来源。

当原票仍有40%残仓时，原票与候补记录同一个 `replacement_group`。组内同时存在两只股票时，两者都不能再次做T，避免一个仓位连续拆成更多碎片。日线退出其中一只后，剩余单一成员自动解除组锁。

候补成交后不再存在未闭合卖出腿，日线计划可以恢复。若候补没有成交，卖出腿仍然保持打开，日线计划继续阻断。

## 运行

从 v3 切换前，必须确认 v3 没有未回补反T腿，然后显式迁移：

```powershell
python Stragety/RedisQMT/A144/A144_v4_CandidateReplacement.py migrate-v3 --mode live --confirm MIGRATE
```

观察模式：

```powershell
python Stragety/RedisQMT/A144/A144_v4_CandidateReplacement.py dayt --mode signal
```

查看状态：

```powershell
python Stragety/RedisQMT/A144/A144_v4_CandidateReplacement.py dayt-status
```

真实运行仍需明确确认：

```powershell
python Stragety/RedisQMT/A144/A144_v4_CandidateReplacement.py dayt --mode live --confirm LIVE
```

生产配置已把这一建议固化为硬闸门：`DAYT_LIVE_ENABLED=False`。在完成严格1分钟、跨阶段和连续账户回测前，DayT只能运行观察模式；A144日线主体可独立运行 `plan/execute`。详见 `analysis/A144_v4_生产优化与回测报告_20260924.md`。

## 验证

```powershell
python -m pytest tests/test_redisqmt_a144_v3.py tests/test_redisqmt_a144_v4.py -q
```

测试覆盖：

- 上涨超过2%不会触发紧急买回。
- 14:50产生候补替代动作，不产生强制原票回补。
- 正常回落回补仍然有效。
- 候补预算、现金缓冲和整手计算。
- 原票归属扣减与候补归属新增。
- 替代组防重复拆仓及单成员解锁。
- 候补成交后关闭缺位腿。
- v4 独立订单标签。
- 候补替代集成状态和账本更新。
