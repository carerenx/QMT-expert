# v45 账户多持仓做T

策略：`Stragety/MiniQMT_Stragety/DayT/DayT_v45_PortfolioT.py`

v45 独立包含 v44 的策略代码，不导入同级旧策略。启动后读取配置账户持仓，对每个持仓代码创建独立的分位趋势信号、正反T及MOM状态机，并保留连接异常告警。各股票使用自己的日线、开盘价、ATR和持仓数量，不共用长飞光纤的阈值。

## 启动

```powershell
# 信号模式也需要账户登录，以读取真实持仓；不会提交订单或模拟成交。
python run_bigqmt.py --strategy Stragety\MiniQMT_Stragety\DayT\DayT_v45_PortfolioT.py --mode signal

# 实盘：确认范围是该账户所有持仓，包括运行后新检测到的持仓。
python run_bigqmt.py --strategy Stragety\MiniQMT_Stragety\DayT\DayT_v45_PortfolioT.py --mode live
```

切换版本时应先退出旧版实盘进程，避免两个进程操作相同账户。新进程不恢复旧进程尚未完成的做T状态；有未完成交易腿时不能把重启当作无缝接管。

## 调度和账户资金

- 每60秒刷新持仓，自动加入持仓数量大于零的新代码；不依赖 `cfg.STOCK_QMT` 指定的单一股票。
- 股票被反T卖至零股后仍保留原任务及买回状态，不因持仓查询中消失而遗忘买回。
- 每只股票独立推进状态机，日常轮询等待会让出执行机会。提交订单及成交确认串行执行；成交等待期间其他股票会延后处理，因此不承诺每只股票严格每30秒完成连接检查。
- 每笔买入前重新读取现金，并扣除其他股票尚未买回的反T/MOM卖出金额乘以1.01的预留。该预留是估算，不能保证上涨后仍足够买回，也无法约束账户之外的手动或其他进程下单。
- 连接异常沿用v44告警逻辑。行情响应有价格并不证明行情时间戳足够新；当前没有新增行情时间戳过期检测或自动重连。

## 参数

参数位于v45文件开头：

```python
CONNECTION_CHECK_INTERVAL_SEC = 30.0
PORTFOLIO_REFRESH_SEC = 60.0
SYMBOL_LOT_OVERRIDES = {}
```

默认每笔100股，688/689开头代码默认200股；特殊标的通过完整代码覆盖单笔数量，例如 `{'600000.SH': 200}`。这只是订单数量配置，不是完整的各市场交易规则识别。

“全部持仓采用同一机制”表示全部纳入计算和状态监控，不等于每只股票都可以立即下单：日线不足、无可卖底仓、资金不足、风险过滤等仍会阻断。不同板块的涨跌幅制度没有在此版本自动识别；沿用原策略9.5%的上涨保护，特殊标的需要另行评估该固定保护是否合适。

## 日志

```text
[PORTFOLIO-ADD] 601869.SH shares=200 lot=100
[PORTFOLIO-ADD] 000001.SZ shares=200 lot=100
[000001.SZ] [QUANTILE-TREND] ...
[000001.SZ] [CONNECTION-ALERT] ...
```

策略日志带完整股票代码；共享连接层原有日志仍保持原格式。日志汇总写入 `portfolio` 标识的v45日志文件。

## 验证

离线测试覆盖：多持仓自动发现与刷新、状态隔离、卖至零后的任务保留、买回资金预留、不同股票的日线请求及缓存隔离、协作调度、数量配置、信号模式禁止下单。未连接实际账户进行实盘验证。
