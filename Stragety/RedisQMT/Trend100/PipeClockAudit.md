# Pipe QMT分钟时标与量额核验

日期：2026-11-02。状态：待验证。为15万元、A股与ETF、无杠杆、年化100%研究取得数据证据，不计算收益，不改变冻结策略。

## 本轮实测范围

使用本仓库Named Pipe桥接0.3.78，明确检查`transport=pipe`。关闭缓存、FormulaServer、自动补数据、前收价回填和订阅；请求未复权原始字段。没有Redis调用、下单或撤单。

本地原分钟样本为600000.SH与510300.SH各54619条。新增2026-10-09股票4995条、ETF5004条Tick快照，包括集合竞价和尾盘。股票最初只下载开盘区间，随后补取此前未请求的09:40之后区间；两份请求分别留档。Tick是行情快照，不是交易所逐笔成交明细，不能证明未被快照捕获的每笔成交价格。

API依据：[QMT Python API第71页及附录5.5](../../../.agents/skills/QMT-expert/references/md/python/python_api.md)、[官方数据结构](https://dict.thinktrader.net/innerApi/data_structure.html)。官方Bar结构只列“成交量”，不据Tick单位描述擅自认证所有Bar的单位或精度。

## 时间边界：已经得到的证据

分别检验将某一分钟内最后Tick的价格、累计量额增量，对应到前一、同一、后一标签的分钟线。2026-10-09两样本均明显支持“盘中标签为前一分钟结束后记录”的解释，但午间与收盘边界不是简单的整日平移。

排除11:29与14:59两个待特殊解释的Tick窗口后，两样本各237个可比较窗口：

| 项目 | 600000.SH | 510300.SH |
|---|---:|---:|
| Tick分钟末价与后一标签Bar收盘价相等 | 237/237 | 237/237 |
| 累计量增量与后一标签Bar成交量相等 | 237/237 | 237/237 |
| 金额增量与Bar金额最大绝对差（元） | 2 | 2 |

这237个窗口也包括尾盘零成交快照，不能称为237个有效连续竞价交易分钟。

边界逐项核验：

- **09:30标签**：与09:25开盘竞价Tick的收盘价、累计成交量和累计成交额完全一致。它不是09:30至09:31的连续竞价Bar。
- **11:30标签**：将11:29起至11:30时点附近的快照增量一并比较，量和收盘价均一致；ETF原来缺少的122手、52779元来自11:30边界快照。股票金额差0，ETF差1元。不能把这个边界差判成一整分钟缺失。
- **15:00标签**：收盘竞价Tick的量额增量和价格均与该标签一致。若错误地把它仅解释为14:59内快照，会漏掉股票12725手、ETF111055手的收盘成交。

这些是两资产一个交易日的已观察结果，不是对全池全部历史日期的时标认证。2026-07-03与2026-08-06两样本Tick各请求一次仍为空，前者不能核验ETF旧尾盘制度，后者不能对齐HF历史样本；不重复补下载。沪市ETF在2026-07-06前后的交易阶段规则继续使用`core/phases.py`的已查证边界。

因此暂未生成可成交240分钟数据。开盘竞价应单独保留，其价格和量额不能无声删除，也不能加到首个连续竞价分钟后当作可成交流动性。后续转换必须同时保留可得时点、竞价标记与原始日线聚合证据；尾盘竞价不能作为普通连续竞价撮合。

两样本均无重复分钟标签、非有限数值；当日Tick累计量额均未出现下降。这些结果只支持本次样本的内部一致性，不证明跨源独立性或整个股票池有效。

以每手100股的假设检查分钟量额时，股票2258条、ETF953条不能满足现有严格的`low×股数≤amount≤high×股数`边界（允许1元）。即使考虑手数取整仍有未解释记录。量的精度、快照采样或金额编码只是可能原因；不能仅凭差异小认定没有问题。

额外请求Tick的`pvolume`，两样本均全为0；不能将这些0当成真实原始股数，也没有据此重写成交量。金额日差及个别分钟2元差的原因尚未获供应方或原始逐笔证据认证。本轮没有修改`core/audit.py`阈值、填平金额或伪造股数。
