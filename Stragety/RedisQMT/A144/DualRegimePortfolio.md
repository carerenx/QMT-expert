# A144 v12 主策略与弱市第二策略

入口：[A144_v12_DualRegimePortfolio.py](A144_v12_DualRegimePortfolio.py)。用户于2026-10-16接受当前研究候选，要求实施自动交易并支持策略中断后重启。该决定不改变既有回测数据，也不表示已获得独立样本验证。

## 策略与切换

统一使用前一完成交易日的数据，两个策略共享一个专用预算和真实可用现金；新建母单时不预支尚未成交的卖出款。主策略最多5只持仓、每天最多2次新建买入母单，单只目标预算上限净值20%；第二策略沿用100%目标母单预算，同时受可用现金及20日均成交额千分之一限制。这里的目标预算不是保证成交仓位。

| 条件 | 主策略 | 第二策略 |
| --- | --- | --- |
| 指数收盘≥MA60，且广度≥40% | 允许满足自身条件的股票买入 | 禁止新买，已有仓位继续管理 |
| 指数收盘<MA60 | 下个可交易时段退出主策略持仓 | 允许满足自身条件的ETF买入 |
| 仅广度<40% | 禁止新买；已有持仓按自身退出条件处理 | 允许满足自身条件的ETF买入 |

主策略承接v10：中证500历史实际成分、60日动量前5%、趋势/成交额/效率过滤、5日广度改善至少5个百分点、入场ATR比例≤6%；退出包括10%硬止损、指数退出、盈利保护、5倍ATR跟踪、MA50破位和领涨资格丢失。主策略采用完成日信号，最早下一交易日09:32下单，不是盘中重新计算日线。

第二策略承接接受的七ETF v25候选：159980.SZ、159981.SZ、159985.SZ为商品趋势组；518880.SH、513100.SH、513500.SH、159920.SZ为回归组。商品组还须前日指数低于MA60，选择60日动量领先者；回归组要求站上MA200、RSI2<10，选择RSI最低者。09:31—09:40完成分钟确认后才可买入。保留4%止损，商品6%止盈/10日到期，回归2%止盈/MA5恢复且估计净收益为正/5日到期。宏观恢复不强制卖出第二策略。

这是新的共享账户实盘实现，不能把第二策略独立账户的历史收益直接作为组合实盘收益。实盘按券商真实成交核算数量和成交额；日志中的费用/PnL使用估计费用，券商对账单才是实际手续费依据。ETF每边万一、每委托最低5元；股票沿用研究综合成本假设，均需与实际账单核对。

## 启动

使用外部Python 3.10或更新版本及项目现有pandas/Redis桥接依赖。QMT内置Python 3.6.8不能运行本入口。QMT桥接服务应正常启动；策略强制检查Redis传输、账户匹配、桥接ping及项目xtquant兼容层。行情失败立即停止，不切换其他数据源，不自动补下载旧分钟数据。

先准备经过核实的中证500成分文件，例如放在本目录 `state/csi500_membership.json`：

```json
{
  "source": "实际采用的官方成分及调整公告来源",
  "valid_through": "20261016",
  "snapshots": {
    "20251009": ["这里应是该生效日完整500个证券代码"],
    "20261012": ["这里应是该生效日完整500个证券代码"]
  }
}
```

示例中的文字数组不可用于交易；必须替换为完整500只。快照日期是调整实际生效日，不是公告发布日期。须覆盖最近6个完成交易日与当日的真实成分；调整跨越这些日期时应提供多个快照。`valid_through`只应延长到已核实的日期。程序会检查日期覆盖、500只唯一代码和行情完整性，但不能单凭文件里的来源文字证明其真实；不要直接采用已确认过期的桥接板块名单。已存在的重建文件可作来源材料，经核实有效期后转换为此结构。启动时记录所用文件SHA256。

```powershell
python .\Stragety\RedisQMT\A144\A144_v12_DualRegimePortfolio.py --mode check --universe .\Stragety\RedisQMT\A144\state\csi500_membership.json --capital 100000

python .\Stragety\RedisQMT\A144\A144_v12_DualRegimePortfolio.py --mode live --universe .\Stragety\RedisQMT\A144\state\csi500_membership.json --capital 100000
```

`check`查询连接、账户、已有订单、状态及当日数据，不发买卖或撤单。`live`持续轮询，执行买卖与撤单；本次开发未启动实盘。例中10万元是示例预算，首次启动不得超过账户实际可用现金；默认100万元。已有状态恢复时继续原资金账本，`--capital`不会充值或重置它。初次执行check也会创建同一状态账本，因此首次检查就应填正确预算。

默认状态文件为 `state/dual_regime_v12.json`。继续交易始终使用相同文件；不要删除状态、改用新状态路径或把该文件作为提交产物。已有账户持仓不自动接管；同代码存在外部持仓时不买入，策略自有数量与券商数量不符时停止。股票T+1按券商可卖数量限制，部分成交保留剩余仓位。

## 中断与重启

直接重新执行原来的live命令即可，不需要手动重置。

1. 账户进程锁阻止同一工作区并行启动同策略，进程被强杀后Windows自动释放锁。
2. 母单预算、次数、退出原因及订单意图先写盘并fsync，再发RPC；状态文件以原子替换方式更新。进程在任一步被杀，重启读取最后完整状态，损坏文件报错而不是静默创建空状态。
3. 重启先按确定的订单标识核对券商累计成交，再更新自有持仓及已应用成交数量；重复收到同一累计成交不会重复记账。撤单请求不会被当作撤单成功，等待终态前不发替代委托。每个已提交子单在下一分钟开始请求撤销，午休和收市前也继续核对、请求撤单。
4. 所有下单通过项目桥接的 `order_stock_batch`，开启严格委托/成交身份幂等检查，使用原标识。在原计划执行分钟内允许幂等恢复“写盘后、发送前”的中断；过期买入不补发。未找到的旧委托继续核对并阻止新订单，绝不因查询为空就认为没有成交。该行为依赖现有桥接支持严格身份查询；服务端不支持或查询失败则停止下单。
5. 主策略补查停机期间遗漏的完成日退出；第二策略补查仍持有仓位从上次处理位置起的分钟退出，按每个历史交易日各自此前MA5计算，首次退出原因一旦触发便保留。当前价格反弹也不会抹去已恢复的退出信号。缺少必要行情时停止，不猜测成交或绕过规则。
6. 不补做错过的开仓，也不伪造停机期间成交。策略/执行代码哈希发生变化时拒绝沿用状态，必须明确迁移；账户、策略和schema不匹配同样拒绝恢复。

进程不运行时，不能执行新的止损判断；券商已接收的委托仍可能成交。重启后的退出只能按届时可成交价格执行，不能保证价格或收益完全不受停机影响。若策略、桥接与券商记录都无法确认一笔旧委托，程序保持阻塞，需要核对券商历史记录；不得删状态强行重开。实际分红、拆并份额、手工交易或费用差异也需对账，程序不自动猜测这些调整。

## 主策略逐步筛选

1. 对股票完整价格历史计算指标，再按每一交易日真实成分计算横截面排名和市场广度；不先裁掉退出成分的历史再算均线。广度分母为该日完整500只成分。
2. 趋势同时要求：复权收盘>MA50、MA20>MA50、MA50高于5日前、60日收益>0且百分位≥70%。在此基础上，领涨入场还要求60日收益百分位≥95%、收盘>MA20。
3. 指数收盘≥指数60日均线，广度≥40%；广度比5个交易日前至少增加0.05。这里是增加5个百分点，例如35%到40%，不是35%乘1.05。
4. 历史至少130条，20日平均成交额≥3000万元，ATR/收盘在1%—6%之间，完成日涨幅<9.5%，20日方向效率≥0.30。
5. 方向效率等于 `(当日复权收盘−20日前复权收盘) / 最近20日收盘变动绝对值之和`，不是胜率。越接近1表示上涨路径越平顺。
6. 候选评分为 `0.7×60日动量百分位 + 0.3×方向效率百分位`，从高到低排序，同分按代码排序。股票母单创建窗口为完成分钟09:31—09:35，对应最早执行09:32—09:36。已有母单可按自己的5分钟寿命继续，不保证首分钟全部成交。

主策略单只权重公式为 `min(20%, 6% / (5×ATR比例))`。例如ATR为4%，计算值是30%，最终受20%上限约束；ATR为6%时计算值正好20%。预算还会被实际可用现金及均成交额限制压低。因此，默认参数下很多股票实际都使用20%目标预算；提高风险预算不一定提高仓位。

主策略退出依次判断硬止损、指数退出、盈利保护、ATR跟踪、MA50破位、领涨排名丢失。盈利保护按持仓期间完成日收盘峰值计算：曾浮盈至少15%后，回到入场收益2%及以下触发；曾浮盈至少30%后，回到10%及以下触发。峰值不是盘中最高价。指数退出与广度不足的处理不同，不能把两者都理解为“立刻全部清仓”。

## 第二策略逐步筛选

商品组使用不复权日线，要求收盘>MA20、60日收益>0、20日均成交额≥3000万元，再选60日收益最高的一个。回归组要求收盘>MA200、RSI2<10、20日均成交额达标，再选RSI2最低的一个。每组只产生一个日线领先候选，组内并列按代码元组的原始顺序取首个。

RSI2使用上涨/下跌绝对变动的指数平均，平滑系数0.5，至少20条预热；上涨和下跌均为0时不产生有效RSI。不能把“RSI越低”理解成价格一定见底，MA200是排除长期弱趋势的一层条件。

商品组分钟买入要求：弱市开关开启、前日指数本身低于MA60、日线领先资格成立，并且已完成分钟收盘≥前日MA20，且≥当日至该分钟的 `(累计最高价+累计最低价)/2`。这个中点不使用未来当日高低，也不是VWAP。

回归组分钟买入要求：弱市开关开启、日线领先资格成立，已完成分钟收盘≥前日收盘。两组创建新母单的完成分钟窗口都是09:31—09:40，实际下单在随后分钟；最后09:40触发的母单，其后续子单可以延续到窗口之后，但仍受母单寿命及停止买入规则限制。每代码每天最多创建2次母单，不是无限做T。

第二策略先按真实已买入成交额/累计买入数量计算平均入场价，再判断完成分钟涨跌幅。退出优先级是4%止损、各组止盈、回归组均线恢复、到期。均线恢复额外估计：

```text
估计卖价 = 将(当前完成分钟最低价 × (1−0.3%))向下取整至0.001元
预计剩余卖出净款 = 估计卖价×剩余份额 − max(5元, 卖出额×万分之一)
估计整笔净收益 = 已卖出额−已卖出估计费用+预计剩余卖出净款−累计买入额−累计买入估计费用
```

只有估计整笔净收益>0，且分钟收盘≥此前完成日MA5，才触发该均线恢复退出。这个门槛为滑点和费用留下余量，不能抵消或保证实际滑点；下一分钟价格、部分成交和真实费用仍可能使实际结果亏损。止损、止盈和到期不受“估计净收益必须为正”限制。

持仓年龄按实际交易日分钟钟表计数，每日240分钟，商品阈值2400分钟、回归1200分钟；达到后还须完成分钟时间≥14:50才触发到期。因此它不是“买入后第5个自然日必卖”。首次入场时间记录为首个发生实际成交的子单的计划执行分钟，券商延迟成交可能使这一分钟标记与实际成交时刻存在偏差；成交数量与成交均价仍来自券商累计回报。本文不把该时间标记声称为逐笔成交时间。

## 阈值在哪里调、怎么调

常用研究参数集中在策略文件顶部，修改 Python 常量，不使用额外JSON参数配置。小数0.04表示4%，0.003表示0.3%，30000000表示3000万元；时间是上海时间的六位字符串，含边界。以下“提高/降低”的影响只是规则方向，不承诺收益或胜率变化。

| 策略文件常量 | 默认值 | 用法与调整影响 |
| --- | --- | --- |
| `BREADTH_MIN` | 0.40 | 站上MA50比例门槛；提高会缩小主策略开放区间、扩大第二策略开放区间，同时改变两边的切换，不只是多筛掉几只股票 |
| `MIN_AVERAGE_TURNOVER` | 30000000 | 两策略20日均成交额最低值；提高偏向更活跃标的，候选通常减少 |
| `MAX_PRIMARY_POSITIONS` | 5 | 主策略持仓/未完成买入母单的代码总上限；增大并不自动分配足额资金 |
| `MAX_PRIMARY_ENTRIES` | 2 | 主策略每天新建母单总数上限；部分成交子单不重新计为新母单 |
| `PRIMARY_LEADER_RANK` | 0.95 | 60日动量百分位门槛；0.95近似前5%，改0.90近似前10%，不是收益率达到95% |
| `PRIMARY_MIN_EFFICIENCY` | 0.30 | 方向效率最低值；提高倾向更平顺的上涨路径 |
| `PRIMARY_EFFICIENCY_WEIGHT` | 0.30 | 评分中的效率权重；动量权重自动为1减此值，保持在0—1之间 |
| `PRIMARY_BREADTH_LOOKBACK` | 5 | 比较广度所隔交易日；增大需提供更多历史成分快照和行情 |
| `PRIMARY_BREADTH_MIN_CHANGE` | 0.05 | 广度至少改善5个百分点；0表示不下降，负值允许下降 |
| `PRIMARY_ENTRY_ATR_MAX` | 0.06 | 入场ATR/收盘上限；增大允许更高波动，原有1%下限仍保留 |
| `PRIMARY_TRAIL_ATR` | 5.0 | 跟踪退出距离的ATR倍数，同时参与权重分母；增大会放宽跟踪止损并降低未受上限约束的目标权重 |
| `PRIMARY_HARD_STOP` | 0.10 | 完成日相对平均入场价的硬止损跌幅；减小会更早触发，但下一时段成交可能越过阈值 |
| `PRIMARY_MAX_WEIGHT` | 0.20 | 主策略单只目标预算占专用净值的上限；不是全账户强制仓位再平衡 |
| `PRIMARY_RISK_BUDGET` | 0.06 | 权重公式的分子；上调只有在未被仓位/现金/流动性上限约束时才增加预算 |
| `PRIMARY_EXIT_RANK` | 0.85 | 持仓动量百分位低于该值退出；上调更容易失去领涨资格 |
| `PRIMARY_PROFIT_ARM_1` / `PRIMARY_PROFIT_LOCK_1` | 0.15 / 0.02 | 第一档盈利保护：峰值浮盈达到15%，之后收益回到2%触发 |
| `PRIMARY_PROFIT_ARM_2` / `PRIMARY_PROFIT_LOCK_2` | 0.30 / 0.10 | 第二档盈利保护；保持第二档触发收益高于第一档，保护收益低于触发收益 |
| `SECONDARY_WEIGHT` | 1.0 | 第二策略新母单目标预算；0.5表示目标净值50%，不是全账户总仓位限制，也不会立即减半已有仓位 |
| `MAX_SECONDARY_ENTRIES` | 2 | 每只ETF每天最多新建母单数；提高会增加反复入场与费用的可能性 |
| `SECONDARY_STOP` | 0.04 | 第二策略分钟止损跌幅；缩小更早退出，也可能增加噪声止损 |
| `COMMODITY_PROFIT` / `COMMODITY_HOLD_DAYS` | 0.06 / 10 | 商品止盈收益阈值/持有交易日等价分钟数；提高止盈阈值可能减少获利退出次数 |
| `REVERSION_MA_DAYS` | 200 | 回归入场的长期均线周期；增加要求更多日线预热，会改变长期趋势资格 |
| `REVERSION_RSI_MAX` | 10 | RSI2严格小于该值才符合资格；提高会放宽超卖条件，10不是10%的价格跌幅 |
| `REVERSION_PROFIT` / `REVERSION_HOLD_DAYS` | 0.02 / 5 | 回归组止盈收益阈值/持有交易日等价分钟数 |
| `REVERSION_RECOVERY_MA_DAYS` | 5 | 均线恢复退出所用周期；修改后代码的`recovery_ma5`字段名仍是历史名称，实际按该常量计算 |
| `SECONDARY_ENTRY_START` / `SECONDARY_ENTRY_END` | 093100 / 094000 | 新母单信号的完成分钟窗口，执行在下一分钟；时间必须属于实际交易分钟 |
| `MEAN_EXIT_SLIPPAGE` | 0.003 | 仅用于回归均线退出的净收益估计；提高会让该出口更难触发，不是券商成交滑点设置 |

参数调整示例：只想把第二策略每次新买预算降到净值一半，可将 `SECONDARY_WEIGHT = 1.` 改成 `.5`；它不会保证总仓位≤50%，还可能降低收益。此前50%对照年化19.22%，未达到20%门槛，不能把降低仓位描述成已验证的收益优化。只想让主策略更早保护盈利，可研究把第一档保护收益从2%提高到4%，保持触发档仍为15%；这样可能更早卖出，也可能错过随后上涨。

实盘调整顺序：先保存原代码及原状态、停止旧进程，使用新版本在独立测试环境验证，再明确迁移已有账本与订单。不要删除状态中的代码哈希来绕过检查；程序设计上拒绝“持有旧仓但悄悄换规则”。本次没有提供自动迁移器，因此已有持仓时的策略变更须另行实现并验证迁移。更换标的、增加做T或其他新增机制，按项目约定另建策略版本；本文件没有把此前表现较差的DayT实验偷偷混入已接受的v25机制。
